# 차량 점검·정비 즉시반영 대시보드

입력 → 화면에 바로 차트 반영 / D1에는 백그라운드로 조용히 저장

## 지금 당장 써보려면 (D1 없이)
`dashboard.html`을 그냥 더블클릭해서 여세요. 상단 "Worker 주소" 칸을 비워두면
D1 저장 없이 이 화면에서만 정비 내역을 입력하고 차트를 바로 확인할 수 있습니다.
(새로고침하면 데이터는 사라집니다 — 테스트용)

## D1에 실제로 저장하려면

### 1. D1 생성 및 테이블 적용
```bash
wrangler d1 create car-instant-db
```
나온 database_id를 `wrangler.toml`에 붙여넣고:
```bash
wrangler d1 execute car-instant-db --remote --file=./schema.sql
```
이 한 번으로 테이블 생성 + 영수증 기준 초기 데이터(엔진오일 139,100원 + 에어컨필터 56,200원)까지 들어갑니다.

### 2. Worker 배포
```bash
wrangler deploy
```

### 3. 대시보드에 연결
`dashboard.html`을 열고 상단 "Worker 주소" 칸에 배포 주소 입력 후 [저장] 클릭. 이후부터:
- 정비 내역 저장 → **화면 차트는 즉시 갱신** (네트워크 기다리지 않음)
- 동시에 백그라운드에서 D1에 저장 ("D1에 저장 완료" 표시)
- 새로고침해도 D1에 저장된 기존 내역을 다시 불러와서 차트에 반영

## 화면 구성
- 차량 기본정보 (투싼 NX4)
- 요약: 총 정비 건수 / 누적 지출액 / 1회 평균 비용
- 소모품 현황 (엔진오일·에어컨필터 등 잔여 주행거리, 앱 캡처 기준 고정값)
- 카테고리별 지출 도넛차트
- 정비 비용 추이 선그래프
- 최근 정비 내역 목록
- 왼쪽 입력 폼 (정비일자/주행거리/업체/작업명/카테고리/비용/메모)

## 왜 Worker가 완전히 없을 수는 없는가
브라우저는 D1에 직접 접속할 수 없어 Cloudflare 구조상 Worker를 거쳐야 합니다. 다만 이 Worker는
`/save`, `/all` 딱 2개 엔드포인트만 있고 집계·차트 계산은 전부 `dashboard.html`의 JavaScript가
처리하므로, "API를 만들었다"기보다 "D1으로 가는 통로를 열었다"에 가깝습니다.

## 검증 완료 사항
- `dashboard.html` JavaScript 문법 오류 없음 확인
- HTML의 모든 `id` 참조가 실제 요소와 정확히 매칭되는지 확인
- `schema.sql`을 로컬 SQLite로 직접 실행 → 초기 데이터 합계(195,300원)가 영수증과 정확히 일치하는 것 확인

⚠️ `worker.js`는 실제 Cloudflare 배포 환경에서만 최종 동작 확인이 가능해서,
이 환경에서는 배포 후 실제 구동 테스트까지는 진행하지 못했습니다.

## 소모품 현황 계산 방식 (업데이트)

이제 소모품 잔여거리는 고정값이 아니라 **"현재 총 주행거리" 입력값**을 기준으로 매번 계산됩니다.

```
잔여거리 = 교체주기(interval) - (현재 총 주행거리 - 기준값(baseline))
```

- **기준값(baseline)**: 그 소모품을 마지막으로 교체한 시점의 주행거리
- 상단 "현재 총 주행거리" 입력창 값을 바꾸면, 모든 소모품의 잔여거리가 즉시 재계산됩니다

### 기준값이 자동으로 갱신되는 경우

정비 내역 입력 폼에서 **카테고리**를 소모품과 일치하는 값으로 선택하고(예: "엔진오일 교환"),
**주행거리**를 입력해서 저장하면, 그 소모품의 기준값이 이번 정비의 주행거리로 자동 갱신됩니다.

예: "엔진오일 교환" · 주행거리 20,000km로 정비 내역을 저장하면
→ 엔진오일 기준값이 20,000km로 갱신되고, 이후 총 주행거리를 20,000km로 입력하면 "10,000km 남음(교체 직후)"으로 표시됩니다.

### 카테고리 ↔ 소모품 매칭표

| 정비 카테고리 | 매칭되는 소모품 |
|---|---|
| 엔진오일 교환 | 엔진오일 및 필터 |
| 에어클리너필터 교환 | 에어 클리너 필터 |
| 에어컨필터 교환 | 에어컨 필터 |
| 브레이크오일 교환 | 브레이크오일 |
| 냉각수 교환 | 냉각수 |
| 타이어 교체 / 점검 / 기타 | 해당 없음 (소모품 기준값에 영향 없음) |

## 차종별로 보기 (업데이트)

이제 여러 차종을 등록하고, **차종별로 소모품 현황·정비 이력·차트를 따로** 확인할 수 있습니다.

### 사용법
1. 왼쪽 상단 "차종 관리" 카드에서 **"보고 있는 차종"**을 선택하면, 그 차종 기준으로 화면 전체(소모품/요약/카테고리별 지출/추이/최근내역)가 바뀝니다.
2. 새 차종은 "새 차종명" 입력 후 [+ 추가]로 등록할 수 있습니다 (기본 소모품 교체주기 템플릿이 자동 적용됨).
3. 정비 내역을 입력할 때도 **"차종"을 선택**해서 저장하면, 그 차종의 기록으로 귀속됩니다.
4. **"차종별 지출 비교"** 차트에서는 등록된 모든 차종의 누적 지출액을 한 화면에서 비교할 수 있고, 현재 선택된 차종만 진한 색으로 강조됩니다.

### 데이터 구조 변화
- 각 차종(`VEHICLES` 배열의 항목)이 자기만의 소모품 기준값(baseline)과 총 주행거리를 따로 갖습니다.
- 정비 내역(`records`)에는 `vehicleId`가 붙어서, 어느 차종의 기록인지 구분됩니다.
- `schema.sql`과 `worker.js`에는 이미 `vehicle_id` 컬럼과 저장 로직이 반영되어 있어, 별도 수정 없이
  `wrangler d1 execute ... --file=./schema.sql`만 실행하시면 됩니다.

## 주유·세차 현황 + 메모 표시 (업데이트)

### 새로 추가된 것
- **⛽ 주유 입력/현황**: 주유일자·주행거리·주유량(L)·금액·주유소를 입력하면, 오른쪽에 주유비 추이 선그래프와
  요약(총 주유횟수, 누적 주유비, L당 평균단가)이 즉시 반영됩니다.
- **🧽 세차 입력/현황**: 세차일자·종류(셀프/자동/손세차/왁스코팅/실내디테일링)·비용·업체를 입력하면,
  세차비 추이 막대그래프와 요약(총 세차횟수, 누적 세차비)이 즉시 반영됩니다.
- 둘 다 **차종별로 구분**되어, 상단에서 차종을 바꾸면 주유/세차 현황도 그 차종 기준으로 바뀝니다.
- 둘 다 정비 내역과 동일한 방식으로 **입력 즉시 화면 반영 + 백그라운드 D1 저장**입니다.

### 버그 수정: 메모 내용이 내역에 안 보이던 문제
"최근 정비 내역" 목록에서 메모(memo) 필드가 화면에 표시되지 않던 부분을 고쳤습니다.
이제 메모를 입력하면 해당 내역 아래에 "📝 메모내용"으로 함께 표시됩니다.

### D1 스키마 추가사항
`schema.sql`에 `fuel_records`, `wash_records` 테이블이 추가됐고, `worker.js`에도
`/save-fuel`, `/all-fuel`, `/save-wash`, `/all-wash` 엔드포인트가 추가됐습니다.
기존과 동일하게 `wrangler d1 execute ... --file=./schema.sql` 한 번만 다시 실행하시면 됩니다.

## 전면 개편: 차종 CRUD, 방향제 관리, 전체 수정/삭제, 전체보기 (업데이트)

### 1. 차종 등록 정보 확장 + 수정/삭제
"차종 관리" 카드에서 이제 **차종명뿐 아니라 차량번호·연료/엔진·소유자까지 함께 입력**합니다.
등록된 차종 목록에 **수정/삭제 버튼**이 생겨서, 정보가 틀렸거나 더 이상 안 쓰는 차량은 바로 고치거나 지울 수 있습니다.
⚠️ 차종을 삭제하면 그 차종에 연결된 정비/주유/세차/방향제 기록도 함께 삭제됩니다 (삭제 전 확인창이 뜹니다).

### 2. 방향제 관리 (신규)
- **오일 충전**: 15일 주기
- **목조필터 교체**: 6개월(180일) 주기
"방향제 관리" 카드에서 차종·유형·시행일자·메모를 입력하면, 오른쪽 "방향제 현황"에 **잔여일 막대그래프**로
바로 표시됩니다 (기록이 없으면 "기록 없음"으로 표시). "방향제 이력"에서 과거 기록도 수정/삭제할 수 있습니다.

### 3. 모든 섹션에 수정/삭제 버튼 추가
정비 내역, 주유 내역, 세차 내역, 방향제 기록 — **네 종류 전부** 목록의 각 항목에 "수정"/"삭제" 버튼이 있습니다.
"수정"을 누르면 해당 입력 폼에 기존 값이 채워지고, 저장 버튼이 "수정 완료"로 바뀝니다. "취소" 버튼으로 수정을 중단할 수 있습니다.

### 4. 주유·세차·방향제 모두 차종 선택 가능
세 입력 폼 모두 자체적인 "차종" 드롭다운이 있어서, 오른쪽 "조회 범위"와 별개로 **어느 차종의 기록인지 매번 선택**해서 저장할 수 있습니다.

### 5. 전체 차종 보기
오른쪽 상단 "조회 범위" 드롭다운에 **"🔷 전체 차종 (합계)"** 옵션이 추가됐습니다.
이걸 선택하면:
- 모든 그래프(카테고리별 지출, 정비 추이, 주유 현황, 세차 현황)가 **전체 차종 합산**으로 표시됩니다
- 소모품 현황·방향제 현황은 차종별로 묶어서(그룹 카드) 각각 따로 보여줍니다
- 목록(정비/주유/세차/방향제 이력)에는 어느 차종 기록인지 이름이 함께 표시됩니다

### D1 동기화 관련 참고사항
- 정비·주유·세차·**방향제** 기록은 모두 D1과 동기화됩니다 (`schema.sql`에 `freshener_records` 테이블,
  `worker.js`에 `/save-freshener`, `/all-freshener` 엔드포인트 추가).
- **차종 자체(이름/번호/연료/소유자, 소모품 기준값)는 아직 D1에 저장되지 않고 이 브라우저에서만 유지**됩니다.
  새로고침하면 차종 목록은 초기 상태(투싼 NX4 1대)로 돌아가지만, D1에 저장된 기록(정비/주유/세차/방향제)은
  다시 불러와집니다. 차종 정보까지 D1에 영구 저장하려면 `vehicles` 테이블과 관련 API를 추가로 만들어드릴 수 있습니다.

### 검증 완료 사항
- 전체 JavaScript 문법 오류 없음 확인
- HTML의 모든 `id` 참조 및 `onclick`/`onchange`/`oninput` 함수 호출이 실제 정의와 정확히 매칭되는지 확인
- 소모품/방향제 잔여 계산 로직을 Node.js로 별도 재현해서 검증 (예: 오일 15일 주기 중 14일 경과 → 1일 남음, 정상 계산 확인)
- `schema.sql` 전체(방향제 테이블 포함)를 로컬 SQLite로 실행해서 정상 생성 확인
- `worker.js` 문법 오류 없음 확인

⚠️ 다만 이번에도 Worker API는 실제 Cloudflare 배포 환경에서만 최종 동작 확인이 가능해서, 배포 후 실제 구동
테스트까지는 진행하지 못했습니다. 배포 중 오류가 발생하면 오류 메시지를 알려주시면 바로 확인해드릴게요.

## 그래프 표시 문제 수정 + 소모품 기본값 재설정 (업데이트)

### 그래프가 안 보이던 원인
직전 버전에서 정비 내역 초기 데이터를 넣지 않고 시작해서, 정비 기록이 하나도 없는 상태에서는
**카테고리별 지출 도넛차트·정비 비용 추이 선그래프가 그릴 데이터 자체가 없어 빈 화면처럼 보였습니다.**
이번 버전에서는:
- 영수증 기준 초기 정비 데이터 3건(엔진오일 SET교환 139,100원 / 활성탄필터 56,200원 / 점검 0원, 합계 195,300원)을 다시 넣어서 **처음 열어도 바로 그래프가 보입니다.**
- 그래도 데이터가 없는 상태(예: 새 차종 추가 직후)에서는 빈 캔버스 대신 **"데이터가 없습니다" 안내 문구**가 뜨도록 개선했습니다 (정비/주유/세차 차트 전부 동일하게 적용).

### 소모품 기본값 재설정
요청하신 대로, **총 주행거리가 0일 때** 아래처럼 표시되도록 소모품 기준값(baseline)을 전부 0으로,
교체주기(interval)를 다음과 같이 맞췄습니다.

| 소모품 | 총주행거리 0일 때 잔여거리 |
|---|---|
| 엔진오일 및 필터 | 10,000km 남음 |
| 에어 클리너 필터 | 10,000km 남음 |
| 에어컨 필터 | 15,000km 남음 |
| 브레이크오일 | 50,000km 남음 |
| 냉각수 | 200,000km 남음 |

이 기본값은 **새로 추가하는 모든 차종에도 동일하게 적용**됩니다. "현재 총 주행거리" 입력창의 기본값도 0으로 바꿨습니다.

### 소모품 현황 차종별 보기
기존에도 지원되던 기능이지만 다시 확인드리면: 오른쪽 상단 "조회 범위"에서 특정 차종을 선택하면 그 차종의

## 전체 차종 비교 그래프 + 모달 방식 수정/삭제 + D1 완전 CRUD (업데이트)

### 1. 전체 차종 조회 시 항목별 비교 그래프 추가
"조회 범위"에서 **"🔷 전체 차종(합계)"**를 선택하면, 기존 "차종별 지출 비교"(정비+주유+세차 합산) 차트
아래에 **"차종별 상세 비교"** 카드가 새로 나타나서:
- 🔧 정비 비용 — 차종별 막대그래프
- ⛽ 주유 비용 — 차종별 막대그래프
- 🧽 세차 비용 — 차종별 막대그래프

세 그래프를 각각 따로 비교할 수 있습니다. 특정 차종을 조회할 때는 이 카드가 자동으로 숨겨집니다.

### 2. 수정/삭제가 전부 모달 방식으로 변경
정비·주유·세차·방향제·**차종 정보**까지, 목록의 "수정" 버튼을 누르면 더 이상 왼쪽 입력 폼이 바뀌지 않고
**화면 중앙에 모달 창**이 뜹니다.
- **수정 모달**: 기존 값이 채워진 입력창 + [수정]/[취소] 버튼. [수정]을 누르면 즉시 반영되고 모달이 닫힙니다.
- **삭제 모달**: "삭제하시겠습니까?" 안내 문구 + [삭제]/[취소] 버튼. [삭제]를 눌러야 실제로 지워집니다.

기존에 사이드바 폼이 "수정 모드"로 바뀌던 방식은 없앴습니다. 사이드바 폼은 이제 **항상 새로 등록하는 용도**로만 쓰입니다.

### 3. D1과 완전히 연동되는 수정/삭제
이전 버전까지는 수정·삭제가 **이 브라우저 화면에서만** 반영되고 D1에는 반영되지 않았습니다.
이번에 `worker.js`를 전면 개편해서:
- 생성(POST)은 이제 **실제 D1에 저장된 id를 응답으로 돌려주고**, 대시보드가 그 id로 자신의 임시 id를 교체합니다
  (그래야 이후 수정/삭제가 정확한 행을 가리킬 수 있습니다)
- **PUT** `/record/:id`, `/fuel/:id`, `/wash/:id`, `/freshener/:id` — 각각 수정 반영
- **DELETE** `/record/:id`, `/fuel/:id`, `/wash/:id`, `/freshener/:id` — 각각 삭제 반영

즉 모달에서 수정·삭제를 하면 화면에 즉시 반영됨과 동시에, 뒤에서 D1에도 PUT/DELETE 요청이 나갑니다.

### 알아두실 점
- **차종(이름/번호/연료/소유자, 소모품 기준값) 자체는 여전히 D1에 저장되지 않고 브라우저에서만 유지**됩니다.
  (정비/주유/세차/방향제 "기록"만 D1과 동기화됩니다.) 새로고침해도 기록은 다시 불러와지지만, 차종 목록은
  초기 상태(투싼 NX4 1대)로 돌아갑니다.
- D1에 아직 저장 중(네트워크 응답 대기)인 아주 짧은 순간에 그 항목을 곧바로 수정/삭제하면, 아직 임시 id
  상태라 D1 쪽 반영이 누락될 수 있습니다. 실사용에서는 거의 발생하지 않는 예외적인 경우입니다.

### schema.sql
이번 업데이트에서는 테이블 구조 변경은 없습니다 (모든 테이블에 이미 `id INTEGER PRIMARY KEY AUTOINCREMENT`가
있어서 수정/삭제에 필요한 기본키가 이미 준비되어 있었습니다). `worker.js`만 대폭 개편됐습니다.

### 검증 완료 사항
- 전체 JavaScript 문법 오류 없음 재확인
- HTML `id` 참조 및 `onclick`/`onchange`/`oninput` 함수 호출 무결성 재확인
- `worker.js` 문법 오류 없음 확인
- 차종별 상세 비교(정비/주유/세차) 계산 로직을 Node.js로 재현하여 정확한 값 산출 확인
- `schema.sql`을 로컬 SQLite로 재실행하여 5개 테이블(maintenance, fuel_records, wash_records, freshener_records, sqlite_sequence) 정상 생성 확인

⚠️ 이번에도 `worker.js`의 실제 배포·구동 테스트(PUT/DELETE 포함)는 Cloudflare 환경에서만 가능해서
진행하지 못했습니다. 배포 후 수정/삭제가 D1에 반영 안 되는 것 같으면, 대시보드 상단의 동기화 상태 메시지를
확인해주시고 오류 메시지를 알려주시면 바로 봐드릴게요.

## 총 주행거리 저장/수정 + 그래프·요약 차종별 구분 (업데이트)

### 1. 총 주행거리를 차종마다 저장/수정
"소모품 현황" 카드의 "현재 총 주행거리" 입력 옆에 **[저장] 버튼**이 생겼습니다.

- JS 문법 오류 없음, HTML id 참조 무결성 재확인

## Worker 없이 바로 저장 (window.storage로 전환) + 세부 기능 업데이트

### ⚠️ 중요: D1과 window.storage는 다른 저장소입니다
- **D1**: Cloudflare의 정식 SQL 데이터베이스. 브라우저가 D1에 직접 접속하는 방법은 **존재하지 않습니다** —
  반드시 Worker(서버)를 하나 두고, 그 Worker가 대신 D1을 읽고 써줘야 합니다. 이건 Cloudflare 플랫폼의
  구조적 제약이라, 저희가 뭘 어떻게 짜도 우회할 수 없습니다.
- **window.storage**: Claude 아티팩트 화면에서 **Worker 없이 브라우저가 바로 읽고 쓸 수 있는 별도의 저장소**입니다.
  예전에 만든 인테리어 체크리스트 댓글 기능이 실제로 쓴 게 이것입니다 (D1이 아니었습니다).

이번 업데이트에서는 **D1+Worker 대신 window.storage로 전면 전환**해서, 배포 과정 없이 바로 쓸 수 있게
만들었습니다. 대신 이 데이터는 Cloudflare D1처럼 외부에서 쿼리하거나, 다른 프로그램과 연동하는 용도로는
쓸 수 없고 **이 Claude 아티팩트 화면 안에서만 유효**합니다.

### 무엇이 바뀌었나
- 상단 "Worker 주소 입력" 칸이 사라지고, **"💾 데이터는 자동으로 저장되며..."** 안내로 바뀌었습니다.
- 정비/주유/세차/방향제/차종 정보를 추가·수정·삭제할 때마다 **자동으로 저장**됩니다 (별도 버튼 없음, 0.3초 디바운스로 여러 변경을 묶어서 저장).
- 화면을 새로고침하거나 다시 열어도 저장된 내용이 그대로 불러와집니다.
- **차종 마스터 정보(이름/번호/연료/소유자, 소모품 기준값)도 이제 함께 저장**됩니다 (기존 D1 버전에서는 기록만 저장되고 차종 정보는 저장 안 됐던 한계가 해결됨).

### 실제 Cloudflare D1이 꼭 필요하시면
`schema.sql` / `worker.js` / `wrangler.toml` 파일은 그대로 남겨뒀습니다. 나중에 "Claude 밖에서도 접근
가능한 진짜 데이터베이스가 필요하다" (예: 다른 앱과 연동, 회사 시스템 연결 등)는 상황이 생기시면
그 파일들로 실제 Cloudflare 배포를 진행하시면 됩니다. 다만 그 경우 화면(dashboard.html)도 그때 다시
window.storage가 아닌 fetch 기반으로 되돌려야 합니다.

### 그 외 변경사항
1. **"카테고리별 지출" → "정비 카테고리별 지출"로 명칭 변경** — 정비 항목의 카테고리라는 게 명확해지도록.
2. **주유 현황 · 세차 현황도 전체 차종 조회 시 차종별로 구분**:
   - 요약 숫자 아래에 **차종별 세부내역**(주유: 횟수·누적액·L당 평균단가 / 세차: 횟수·누적액)이 목록으로 추가됩니다.
   - 그래프도 차종마다 **별도의 선(line)**으로 그려져서, 추이를 차종별로 비교할 수 있습니다.
   - 특정 차종을 선택하면 기존처럼 그 차종만의 단순 그래프로 돌아옵니다.

### 검증
- 전체 JavaScript 문법 오류 없음, HTML id/함수 참조 무결성 재확인
- 주유 차종별 세부내역(횟수/누적액/L당 평균단가) 계산 로직을 Node.js로 재현하여 정확한 값 확인

## D1+Worker로 복귀 + API 주소를 화면에서 숨김 (업데이트)

지난 업데이트에서 window.storage로 전환했었는데, **다시 D1+Worker 방식으로 되돌렸습니다.**
`worker.js`/`schema.sql`은 이전에 만들어둔 것을 그대로 사용합니다 (변경 없음).

### API 주소 입력창을 화면에서 없앰
이전에는 상단에 "Worker 주소 입력" 칸이 있어서 사용자가 직접 타이핑해야 했는데, 이번에는
**`dashboard.html` 소스 코드 안에 고정 상수로 넣는 방식**으로 바꿨습니다.

`dashboard.html`을 열어서 `<script>` 태그 안, 아래 부분을 찾으세요:

```js
// ⚠️ 배포한 Worker 주소를 아래에 직접 넣으세요. (예: 'https://car-instant-db.xxx.workers.dev')
// 비워두면(빈 문자열) 이 화면에서만 동작하고 D1에는 저장되지 않습니다.
const API_BASE = '';
```

따옴표 안에 실제 배포한 Worker 주소를 넣고 저장하시면 됩니다.

```js
const API_BASE = 'https://car-instant-db.본인계정.workers.dev';
```

이렇게 해두면 화면 어디에도 API 주소가 노출되지 않고, 대시보드를 여는 누구에게나 동일하게 D1 데이터가
보이게 됩니다 (팀원과 공유할 때 API 주소를 매번 알려줄 필요가 없어집니다).

### 배포 순서 (다시 정리)
```bash
wrangler d1 create car-instant-db
wrangler d1 execute car-instant-db --remote --file=./schema.sql
wrangler deploy
```
배포 후 나온 주소를 위 `API_BASE`에 붙여넣고 `dashboard.html`을 다시 저장하면 끝입니다.

### 참고
- `API_BASE`를 비워두면(`''`), 상단에 "⚠ API 주소가 설정되지 않음 (이 화면에서만 동작)"이라고 표시되고,
  데이터는 저장되지 않은 채 이 화면에서만 임시로 동작합니다. 테스트용으로 쓰실 수 있습니다.
- 이전과 동일하게 **차종 마스터 정보(이름/번호/연료/소유자, 소모품 기준값)는 D1에 저장되지 않고 이
  브라우저에서만 유지**됩니다. 정비/주유/세차/방향제 "기록"만 D1과 동기화됩니다.

### 검증
- JS 문법 오류 없음, HTML id/함수 참조 무결성 재확인
- `window.storage` 관련 코드가 완전히 제거되고 D1/Worker fetch 기반으로만 동작하는지 재확인

## 차종 정보(총 주행거리 포함)가 실제로 D1에 저장되지 않던 문제 수정

`car-service-management-dashboard.iregg413.workers.dev`에서 확인해보니, **차종 정보(이름/번호/연료/소유자/총 주행거리)가
D1에 저장되지 않고 있는 게 맞았습니다.** "저장되었습니다" 메시지는 떴지만, 실제로는 브라우저 메모리에만 반영되고
새로고침하면 코드에 있는 기본값(투싼 NX4, 총주행거리 0)으로 되돌아가는 구조였습니다.

차종 정보를 담는 테이블 자체가 없었습니다.

### 수정 내용

**1. `schema.sql`에 `vehicles` 테이블 추가**
```sql
CREATE TABLE IF NOT EXISTS vehicles (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  plate TEXT,
  fuel_engine TEXT,
  owner TEXT,
  total_mileage INTEGER DEFAULT 0,
  consumables_json TEXT,
  created_at TEXT DEFAULT (datetime('now','localtime'))
);
```
소모품 기준값(엔진오일 교체주기 등)은 구조가 복잡해서 JSON 문자열로 통째로 저장합니다.

- `GET /vehicles` — 전체 차종 조회
- `POST /vehicles` — 차종 생성
- `PUT /vehicles/:id` — 차종 수정 (총 주행거리 변경도 이 경로로 저장됨)
